# CHERIoT memory subsystem FPV requirements

What the CHERIoT memory subsystem must do, one testable requirement per row, grouped by feature.

* Each row: the requirement, its sources, then what checks it and why.
* Kind `spec`: a specification states the rule. Kind *RTL*: the rule follows the design's present behaviour.
* A group's Conditions say when its rows hold.
* A value that the instance sets is written as a parameter ([Parameters](#parameters)).
* How it fits together: [CHERIoT memory subsystem FPV testplan](README.md#how-the-plan-fits-together). The same rows as data: [`cheriot_mem_sys_fpv_requirements.hjson`](../../data/cheriot_mem_sys_fpv_requirements.hjson).

## Terms

| Term | Meaning |
|---|---|
| CHERIoT mode | The mode enable `cheriot_ena_i` is exactly `MuBi4True`. Any other value, an invalid encoding included, is ePMP mode ([Block Diagram](../theory_of_operation.md#block-diagram), [Revocation Engine](../theory_of_operation.md#revocation-engine); [cheriot_mem_sys.hjson `INTERSIG.MUBI`](../../data/cheriot_mem_sys.hjson)). |
| Tag path | The path that stores and returns the tags: the core's tag filter, the WTRC, the 2:1 tag arbiter and the RMW filter, up to the meta SRAM. |
| Hinted capability load | A read of both words of a capability with the tag sideband set, which asks for the tag ([load_store_unit.rst, Data-Side Memory Interface](../../../../vendor/lowrisc_ibex/doc/03_reference/load_store_unit.rst)). |
| W0, W1 | The lower and the upper 32-bit word of a capability. The core sends W0 first ([Write-to-Read-and-Compare Filter (WTRC)](../theory_of_operation.md#write-to-read-and-compare-filter-wtrc)). |
| Capability store to the NVM | A write in CHERIoT mode to the NVM with the tag sideband set ([Write-to-Read-and-Compare Filter (WTRC)](../theory_of_operation.md#write-to-read-and-compare-filter-wtrc)). The WTRC handles it. |
| Sweep | One run of the revocation engine over `TBRE_NUM_CAPS` capabilities from `TBRE_BASE_ADDR` ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |
| Watch window | For one capability of a sweep: from the engine presenting the read of its lower word until its clear is presented. A core write in it keeps its tag ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |
| TRVK filter | The load barrier on the engine's reads: it revokes a tagged, non-sealing capability whose base has its revocation bit set, or whose bitmap lookup fails ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |
| `fatal_fault` | The subsystem's one fatal alert ([Security Alerts](../interfaces.md#security-alerts)). |
| Tagged region | The main SRAM, from `MainSramBaseAddr` up to `MainSramTopAddr`, or the NVM, from `NvmBaseAddr` up to `NvmTopAddr`: the memory that can hold capabilities ([Meta SRAM Address Map](../theory_of_operation.md#meta-sram-address-map)). |
| Meta request | A request the tag filter sends on its meta port, to read or to write one tag. |
| Captured tag | The tag a W0 load returns, held by the tag filter for the W1 load that follows ([Tag Filter](../theory_of_operation.md#tag-filter)). |
| Requester ports | The four ports that reach the meta SRAM: the tag port (from the RMW filter), `corerevbm_tl` (bitmap reads from the core's TRVK filter), `revbm_tl_d` (software, through `xbar_main`) and the revocation engine's TRVK port ([Block Diagram](../theory_of_operation.md#block-diagram), [Meta SRAM Address Map](../theory_of_operation.md#meta-sram-address-map), [Access Checkers](../theory_of_operation.md#access-checkers), [Timing](../theory_of_operation.md#timing)). |
| Tag path access | A request on the tag port. |
| Region of a port | The tag port owns both capability tag regions, the NVM capability tags and the main SRAM capability tags, `0x1100_0C00`-`0x1100_97FF`. The other three requester ports own the revocation bitmap, `0x1100_0000`-`0x1100_0BFF` ([Meta SRAM Address Map](../theory_of_operation.md#meta-sram-address-map), column "Reachable from"). |
| Legal request | All four conditions of [Access Checkers](../theory_of_operation.md#access-checkers) hold: CHERIoT mode; the address inside the port's region; a full 32-bit word at a word-aligned address (`a_size` = 2, so TL-UL sets all four `a_mask` bits: [Request Channel (Channel A)](../../../tlul/doc/TlulProtocolChecker.md#request-channel-channel-a), `sizeMatchesMask`); the opcode `Get` or `PutFullData`. |
| Error answer | The answer an access checker gives a request that is not legal, from its own error responder ([Access Checkers](../theory_of_operation.md#access-checkers)). |
| Base | The lowest address a capability covers, decoded from its address and its bounds fields (CHERIoT architecture specification v1.0, section 7.13.3 (PDF pages 69-70)). |
| Sealing capability | A capability whose permissions are in the sealing format and grant SE, US or U0, the capabilities that the instruction CLC exempts (the CHERIoT architecture specification v1.0, CLC, PDF page 114). The base of a sealing capability is in a namespace of its own, so such a capability is never revoked (CHERIoT architecture specification v1.0, section 7.8 (PDF page 58)). |
| Revocation bit of a base | Bit `b` of bitmap word `w`, with `w * 32 + b` = (base - `MainSramBaseAddr`) / 8 ([Meta SRAM Address Map](../theory_of_operation.md#meta-sram-address-map)). The engine uses the bit of the capability's base, not of its address ([Revocation Engine](../theory_of_operation.md#revocation-engine); CHERIoT architecture specification v1.0, section 7.8 (PDF page 58)). For example, base `0x1000_4000` is word 64, bit 0. |
| Taken start | A write of 1 to `TBRE_START` while `TBRE_REGWEN` is 1, in CHERIoT mode, with `TBRE_NUM_CAPS` not zero and `TBRE_BASE_ADDR` in a tagged region ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |
| Ignored start | Any other write of 1 to `TBRE_START` while `TBRE_REGWEN` is 1 ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |
| BASE, NUM | The values of `TBRE_BASE_ADDR` and `TBRE_NUM_CAPS` at the start. |
| Swept capabilities | The N capabilities at BASE, BASE + 8,..., with N = min(NUM, (top - BASE) / 8) and top the `MainSramTopAddr` or `NvmTopAddr` of BASE's region ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |
| Active | `TBRE_REGWEN` is 0 ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |
| Revoked | A swept capability whose tag is set, which is not a sealing capability, whose base lies in the main SRAM region, and whose base's revocation bit is set or whose bitmap lookup failed ([Revocation Engine](../theory_of_operation.md#revocation-engine); [Revoking Capabilities](../programmers_guide.md#revoking-capabilities)). |
| Touches | A core write touches a capability when it is presented on `cored_tl_d`, or accepted there and not yet answered, with its address in the capability's 8 bytes ([Revocation Engine](../theory_of_operation.md#revocation-engine)). |

## Parameters

The instantiation of the block sets the values below, and they differ from one chip to the next.
The requirements name each value by its parameter, so the same rows hold for every instantiation.

| Parameter | Meaning | Value on Earl Grey |
|---|---|---|
| `MainSramBaseAddr` | Base address of the main SRAM region, inclusive. | `0x1000_0000` |
| `MainSramTopAddr` | Top address of the main SRAM region, exclusive. | `0x1003_0000` |
| `NvmBaseAddr` | Base address of the NVM region, inclusive. | `0x3000_0000` |
| `NvmTopAddr` | Top address of the NVM region, exclusive. | `0x3020_0000` |
| `MetaSramBaseAddr` | Base address of the unified meta SRAM. | `0x1100_0000` |

## Tag filter

Conditions:

* Every row holds for each access that the core presents, except a capability store to the NVM.
* The [WTRC](#wtrc) group covers a capability store to the NVM.

Testpoints: [`tf_forward`](../../data/cheriot_mem_sys_fpv_testplan.hjson#tf_forward) (V1, priority 1), [`tf_lookup`](../../data/cheriot_mem_sys_fpv_testplan.hjson#tf_lookup) (V1, priority 1), [`tf_meta_request`](../../data/cheriot_mem_sys_fpv_testplan.hjson#tf_meta_request) (V1, priority 1), [`tf_sticky_tag`](../../data/cheriot_mem_sys_fpv_testplan.hjson#tf_sticky_tag) (V1, priority 1), [`tf_errors`](../../data/cheriot_mem_sys_fpv_testplan.hjson#tf_errors) (V2S, priority 2), [`tf_flow`](../../data/cheriot_mem_sys_fpv_testplan.hjson#tf_flow) (V2, priority 2).

## WTRC

Security-relevant ([Groups](#groups)).

Conditions:

* The rows apply to a capability store to the NVM and to the requests around it.
* Every other access passes the WTRC unchanged, and the [Tag filter](#tag-filter) rows cover it with the WTRC in place.
* The WTRC tracks the capability being stored, and it treats a word as out of sequence in four cases ([Write-to-Read-and-Compare Filter (WTRC)](../theory_of_operation.md#write-to-read-and-compare-filter-wtrc)).
* With no capability open, a W1 is out of sequence.
* After a W0, anything except the W1 of the same capability is out of sequence.
* After a W1 that is neither answered nor turned into a tag write, a W1 and any other request are out of sequence.
* After the tag write of a W1 is issued, a W1 is out of sequence, and so is a W0 before the W1 is answered.
* A word is matched when its NVM read succeeded, it is a full-word `PutFullData` in sequence, and its data and data integrity equal the NVM's ([Write-to-Read-and-Compare Filter (WTRC)](../theory_of_operation.md#write-to-read-and-compare-filter-wtrc)).

Testpoints: [`rmw_read`](../../data/cheriot_mem_sys_fpv_testplan.hjson#rmw_read) (V1, priority 1), [`rmw_write_skip`](../../data/cheriot_mem_sys_fpv_testplan.hjson#rmw_write_skip) (V1, priority 2), [`rmw_write_back`](../../data/cheriot_mem_sys_fpv_testplan.hjson#rmw_write_back) (V1, priority 1), [`rmw_single_op`](../../data/cheriot_mem_sys_fpv_testplan.hjson#rmw_single_op) (V2, priority 2), [`rmw_errors`](../../data/cheriot_mem_sys_fpv_testplan.hjson#rmw_errors) (V2S, priority 2).

| ID | Requirement and sources | Checked by, and why |
|---|---|---|
| <a id="req_rmw_01"></a>REQ_RMW_01 | A read shall be forwarded to the meta SRAM at its meta word address. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_read`: *Get of its meta word*. The check compares the `Get`'s address with the read's meta word. Another word fails it. |
| <a id="req_rmw_02"></a>REQ_RMW_02 | A read's response without `d_error` shall return, as the tag, the bit of the response word that its bit select names. The tag of an error response is not checked. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter); [load_store_unit.rst, Protocol](../../../../vendor/lowrisc_ibex/doc/03_reference/load_store_unit.rst) | `rmw_read`: *returns its tag bit*. The check picks the bit out of the word read and compares it with the answer's tag. Another bit fails it, because the check runs with every neighbouring bit different from its word. |
| <a id="req_rmw_03"></a>REQ_RMW_03 | A write shall first issue a full-word `Get` of its meta word. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_skip`: *full-word Get first*, *answer after Get answer*. The first check requires a full-word `Get` as the write's first request. The second makes sure the write is not answered before that `Get` comes back. |
| <a id="req_rmw_04"></a>REQ_RMW_04 | A write whose tag equals the stored bit shall issue no write-back. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_skip`: *no write-back*. A write-back presented when the bit already equals the tag fails the check. |
| <a id="req_rmw_05"></a>REQ_RMW_05 | A write with no write-back shall be answered with an `AccessAck`. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_skip`: *answered with AccessAck*, *answer after Get answer*. The first check compares the answer's opcode with `AccessAck`. The second makes sure it comes only once the `Get` answer has arrived. |
| <a id="req_rmw_06a"></a>REQ_RMW_06a | A write whose tag differs from the stored bit shall write back the read word with *that bit set to the tag*. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_back`: *carries the updated word*. The check computes the updated word from the word read and compares it with the write-back. A bit not set to the tag fails it. |
| <a id="req_rmw_06b"></a>REQ_RMW_06b | A write-back shall leave *every other bit* of the read word unchanged. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_back`: *carries the updated word*. The same comparison covers all 32 bits, so any other bit changed fails it. The check runs with every other bit of the word at 0 and at 1. |
| <a id="req_rmw_07a"></a>REQ_RMW_07a | The write-back shall be a full-word *`PutFullData`* to the same meta word. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_back`: *full-word Put to same word*. The check compares the opcode, the size, the mask and the address with a full-word write to the word read. Any difference fails it. |
| <a id="req_rmw_07b"></a>REQ_RMW_07b | The write-back shall carry a freshly computed *command integrity*. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_back`: *full-word Put to same word*. The check recomputes the write-back's command integrity. The `Get`'s integrity left in place fails it. |
| <a id="req_rmw_07c"></a>REQ_RMW_07c | The write-back shall carry a freshly computed *data integrity*. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_back`: *full-word Put to same word*. The check recomputes the data integrity over the updated word. The integrity of the word read fails it, because one bit changed. |
| <a id="req_rmw_08"></a>REQ_RMW_08 | The write-back's response shall be forwarded as the write's response. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_back`: *write-back answer passed up*. The check requires the write's answer in the cycle of the write-back's answer, with its opcode and error. An answer taken from the `Get` fails it. |
| <a id="req_rmw_09"></a>REQ_RMW_09 | Every request issued for a write shall carry the write's `a_source`. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_write_back`: *keeps the write's source*. The check compares the `a_source` of the `Get` and of the write-back with the write's. Another ID fails it. |
| <a id="req_rmw_10"></a>REQ_RMW_10 | A new request shall be accepted only in a cycle with no unanswered operation, or in which the only unanswered operation is a read answered in that cycle. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_single_op`: *one operation at a time*. A request accepted while an earlier operation is still unanswered, other than a read answered in that cycle, fails the check. |
| <a id="req_rmw_11"></a>REQ_RMW_11 | A read presented in the cycle the previous read is answered shall be accepted in that cycle, if the meta SRAM side is ready. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_read`: *back-to-back read accepted*. The check requires the next read to be accepted in the cycle the previous one is answered. A cycle lost fails it. |
| <a id="req_rmw_13"></a>REQ_RMW_13 | A device error on the `Get` of a write shall abort the write: no write-back. <br><br>*Sources:* [Error Handling](../theory_of_operation.md#error-handling) | `rmw_errors`: *Get error stops the write*. A write-back presented after a `Get` answer with `d_error` fails the check, whether or not the bit differs. |
| <a id="req_rmw_14"></a>REQ_RMW_14 | A device error on a meta SRAM response shall be answered upstream with `d_error`. <br><br>*Sources:* [Error Handling](../theory_of_operation.md#error-handling) | `rmw_errors`: *error passed up*. The check requires `d_error` upstream for every operation with an error from the meta SRAM. A lost error fails it. |
| <a id="req_rmw_15a"></a>REQ_RMW_15a | Every accepted request shall in the end be answered, given the meta SRAM answers. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_single_op`: *every operation answered*. The formal tool looks for a run where an operation is never answered while the meta SRAM answers. Such a run fails the check. |
| <a id="req_rmw_15b"></a>REQ_RMW_15b | No accepted request shall be answered twice. <br><br>*Sources:* [Source ID requirements for device elements](../../../tlul/README.md#source-id-requirements-for-device-elements) | `rmw_single_op`: *one answer per operation*. After its answer an operation is closed, so a second answer finds no open operation and fails. |
| <a id="req_rmw_16a"></a>REQ_RMW_16a | The RMW filter shall send the meta SRAM at most *one `Get`* of the meta word per accepted request. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_single_op`: *nothing else downstream*. Each request allows its `Get` once. A second `Get`, or one with no request, fails the check. |
| <a id="req_rmw_16b"></a>REQ_RMW_16b | The RMW filter shall send the meta SRAM a *`PutFullData` write-back* only for a write whose tag differs from the stored bit, and at most one per write. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter) | `rmw_single_op`: *nothing else downstream*. A write-back is allowed once, and only for the current write whose bit differs. A write-back for a read, for an equal bit, or a second one fails the check. |
| <a id="req_rmw_17"></a>REQ_RMW_17 | `d_error` upstream shall be clear when neither the `Get` answer nor the write-back answer of the operation has a device error. <br><br>*Sources:* [RMW Filter](../theory_of_operation.md#rmw-filter); [Error Handling](../theory_of_operation.md#error-handling) | `rmw_errors`: *no error without a cause*. An answer with `d_error` whose `Get` and write-back answers had none fails the check. |
| <a id="req_rmw_18"></a>REQ_RMW_18 | Every `Get` the RMW filter generates shall carry a valid command integrity. <br><br>*Sources:* [Description](../../README.md#description); [cheriot_mem_sys.hjson `BUS.INTEGRITY`](../../data/cheriot_mem_sys.hjson) | `rmw_read`: *Get carries valid integrity*. The check recomputes the command integrity of every `Get`, for reads and writes. Nothing else checks it: the TL-UL bus checker leaves integrity free. |

| ID | Requirement and sources | Checked by, and why |
|---|---|---|

Testpoints: [`meta_forward`](../../data/cheriot_mem_sys_fpv_testplan.hjson#meta_forward) (V1, priority 2), [`meta_refuse`](../../data/cheriot_mem_sys_fpv_testplan.hjson#meta_refuse) (V2S, priority 2).

| ID | Requirement and sources | Checked by, and why |
|---|---|---|
| <a id="req_meta_01a"></a>REQ_META_01a | A legal request on a requester port shall be forwarded to `meta_sram_tl`. <br><br>*Sources:* [Access Checkers](../theory_of_operation.md#access-checkers); [Arbitration](../theory_of_operation.md#arbitration) | `meta_forward`: *legal request forwarded*. | <a id="req_meta_06"></a>REQ_META_06 | No request whose opcode is not `Get` or `PutFullData` shall reach `meta_sram_tl`. <br><br>*Sources:* [Access Checkers](../theory_of_operation.md#access-checkers); [Error Handling](../theory_of_operation.md#error-handling) | `meta_refuse`: *only Get or PutFullData*. ## End-to-end requirements

Security-relevant ([Groups](#groups)).

Conditions:

* The rows state end-to-end behaviour that no single checker decides.
