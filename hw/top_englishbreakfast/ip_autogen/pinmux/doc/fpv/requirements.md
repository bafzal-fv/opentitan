# Pinmux FPV requirements

What the English Breakfast pinmux must do, one testable requirement per row, grouped by feature.

* Each row: the requirement, its sources, then what checks it and why.
* Kind `spec`: a specification states the rule. Kind *RTL*: the rule follows the design's present behaviour.
* A group's Conditions say when its rows hold.
* How it fits together: [Pinmux FPV testplan](README.md#how-the-plan-fits-together). The same rows as data: [`pinmux_fpv_requirements.hjson`](../../data/pinmux_fpv_requirements.hjson).

This page is rendered for this top from the pinmux template by `make -C hw top`.
The plan was written and reviewed for Earl Grey only: no requirement has been read against this top's specification, so every requirement is open.

## Terms

| Term | Meaning |
|---|---|
| `n` | MIO peripheral input (0 to 37) |
| `k` | MIO peripheral output (0 to 34) |
| `p` | MIO pad (0 to 46) |
| `d` | DIO pad (0 to 13) |
| Watched signal | The pad input that `MIODIO` and `PADSEL` pick |
| Forwarded value | The watched signal sampled each `clk_aon_i` cycle, through the filter when `FILTER` is 1 |
| Asleep, awake | A pad is asleep while its sleep status bit is 1, awake while it is 0 |
| AON | The always-on domain: the logic on `clk_aon_i` and `rst_aon_ni` |
| Lands | A written or sampled value lands in the cycle the register or flop it is meant for takes it |
| Hardware write | A write to a register field made by the pinmux logic, not by software over the bus |
| Full reset | A reset that asserts `rst_sys_ni`, which the top connects to the system reset tree ([top_englishbreakfast.hjson](../../../../data/top_englishbreakfast.hjson)) |
| NDM reset | A reset that asserts `rst_ni` and `rst_aon_ni`, not `rst_sys_ni`: the top connects those two to the life cycle reset tree ([top_englishbreakfast.hjson](../../../../data/top_englishbreakfast.hjson)), the tree a non-debug module reset request asserts outside PROD and PROD_END ([Summary](../../../rstmgr/doc/theory_of_operation.md#summary)); what is on `rst_sys_ni` survives it ([Non-debug Module Reset](../../../../../top_earlgrey/ip_autogen/pinmux/doc/theory_of_operation.md#non-debug-module-reset)) |
| On, Off | On is 4'b0101 and Off 4'b1010, the life cycle controller's values ([Control Signal Propagation](../../../../../ip/lc_ctrl/doc/interfaces.md#control-signal-propagation)) |
| The latch | The latched debug enable, seen on `pinmux_hw_debug_en_o` and through the RISC-V TAP |
| A clear | `lc_hw_debug_clr_i`, `lc_check_byp_en_i` or `lc_escalate_en_i` at any value other than Off ([Non-debug Module Reset](../../../../../top_earlgrey/ip_autogen/pinmux/doc/theory_of_operation.md#non-debug-module-reset); [Control Signal Propagation](../../../../../ip/lc_ctrl/doc/interfaces.md#control-signal-propagation) for the debug clear and the escalation input); it turns the latch Off |
| Connected | A TAP is connected while the TAP straps name it and its gate is open: the life cycle TAP at straps 01; the RISC-V TAP at straps 10 while the latch is On; the DFT TAP at straps 11 while `lc_dft_en_i` is On; on a top with the RRAM TAP (`enable_rram_tap`), the RRAM TAP at straps 00 while `RRAM_JTAG_SEL` is `kMultiBitBool4True` and `lc_nvm_debug_en_i` is On; at straps 00, no TAP otherwise ([Strap Sampling and TAP Isolation](../theory_of_operation.md#strap-sampling-and-tap-isolation), [Non-debug Module Reset](../../../../../top_earlgrey/ip_autogen/pinmux/doc/theory_of_operation.md#non-debug-module-reset)) |
| Owns | A TAP owns the JTAG pads while it is connected: the pads then carry the TAP's signals, not what the pad muxes select |
| Cut | A TAP is cut while its gate is shut, or while the TAP straps name another TAP or none |

## Pad attributes

Conditions:

* Every row holds in every cycle, asleep or awake, except on a JTAG pad while a TAP owns it.
* "Written" means a write the register block accepts, its lock open (Register locks); "reads back" means what a read of the register returns.
* A pad type "keeps" an attribute bit when its pads implement that bit ([Pad Attributes](../programmers_guide.md#pad-attributes)), the same on every pad of the type and for good.
* A one-bit field is kept when its bit is; each bit of `slew_rate` and `drive_strength` is kept or not on its own ([Pad Attributes](../programmers_guide.md#pad-attributes)).

## Wakeup detectors

Conditions:

* `w` is a detector (0 to 7); a cycle is a `clk_aon_i` cycle; the watched signal and the forwarded value are defined in the [Terms](#terms).
* Register values are those the AON logic holds once a write has crossed.
* The rows hold with the mode unchanged while enabled, the other fields free to change.
* They hold whatever `sleep_en_i`, `clk_i` (stopped included) and the scan mode do, except scan mode True while the detector watches a scan clock pad.
* They are checked from the filter's fourth sample after `rst_aon_ni`.
* The timed rows ([`REQ_WKUP_09a`](#req_wkup_09a) to [`REQ_WKUP_10b`](#req_wkup_10b)) hold for `CNT_TH` 1 and above.

## USB wakeup

Conditions:

* The module is usbdev's AON/Wake module ([USB Wakeup Detection Module](../../../../../top_earlgrey/ip_autogen/pinmux/doc/theory_of_operation.md#usb-wakeup-detection-module)); each port below has the role usbdev's docs give the port it connects to:

| Port | Role |
|---|---|
| `usbdev_dppullup_en` | D+ pull-up enable, routed to the module's input `usbdev_dppullup_en_i` ([AON/Wake Interface Pins](../../../../../ip/usbdev/doc/theory_of_operation.md#aonwake-interface-pins)) |
| `usbdev_dnpullup_en` | D- pull-up enable, routed to the module's input `usbdev_dnpullup_en_i` ([AON/Wake Interface Pins](../../../../../ip/usbdev/doc/theory_of_operation.md#aonwake-interface-pins)) |
| `usbdev_suspend_req` | "Request to activate the AON/Wake module" ([Inter-Module Signals](../../../../../ip/usbdev/doc/interfaces.md#inter-module-signals)) |
| `usbdev_wake_ack` | "Acknowledge a wake signal from the AON/Wake" ([Inter-Module Signals](../../../../../ip/usbdev/doc/interfaces.md#inter-module-signals)) |
| `usb_dppullup_en` | D+ pull-up enable from the module's output `usb_dppullup_en_o` ([AON/Wake Interface Pins](../../../../../ip/usbdev/doc/theory_of_operation.md#aonwake-interface-pins)) |
| `usb_dnpullup_en` | D- pull-up enable from the module's output `usb_dnpullup_en_o` ([AON/Wake Interface Pins](../../../../../ip/usbdev/doc/theory_of_operation.md#aonwake-interface-pins)) |
| `usbdev_bus_not_idle` | The event "the USB is in a non-idle state" ([Inter-Module Signals](../../../../../ip/usbdev/doc/interfaces.md#inter-module-signals)) |
| `usbdev_bus_reset` | The event "a USB Bus Reset occurred" ([Inter-Module Signals](../../../../../ip/usbdev/doc/interfaces.md#inter-module-signals)) |
| `usbdev_sense_lost` | The event "the VBUS/SENSE signal became deasserted" ([Inter-Module Signals](../../../../../ip/usbdev/doc/interfaces.md#inter-module-signals)) |
| `usbdev_wake_detect_active` | "the external AON/Wake module is active" ([Inter-Module Signals](../../../../../ip/usbdev/doc/interfaces.md#inter-module-signals)): the module's output `wake_detect_active_aon_o` ([AON/Wake Interface Pins](../../../../../ip/usbdev/doc/theory_of_operation.md#aonwake-interface-pins)) |

* A suspend request is a `clk_aon_i` cycle with `usbdev_suspend_req` at 1, a wake acknowledge one with `usbdev_wake_ack` at 1.
* The USB lines are the module's D+, D- and VBUS inputs, free at any time; the module is active while `usbdev_wake_detect_active` is 1.
* Idle (J state) is, with one pad pull-up enable at 1, that line at 1 and the other at 0; with none or both, the bus-not-idle event is not checked.
* The two pull-up rows hold with usbdev's pull-up enables unchanged just before the suspend request.
* The wiring rows follow usbdev's documents; the pinmux theory of operation names only `usb_wkup_req` ([USB Wakeup Detection Module](../../../../../top_earlgrey/ip_autogen/pinmux/doc/theory_of_operation.md#usb-wakeup-detection-module)).
